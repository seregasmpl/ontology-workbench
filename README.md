# Конструктор интуитивных онтологий

Локальное приложение для экспертной работы с понятиями и разметкой текстов. Эксперт определяет категории и связи, проверяет примеры, уточняет правила и запускает автоматическую разметку через собственный API. Интерфейс работает в браузере; проекты хранятся в SQLite на компьютере пользователя.

Предварительная версия 0.1.0. Автоматические проверки проходят на двух учебных онтологиях и имитациях API. Подключения к настоящим провайдерам и полный пользовательский проход ещё требуют проверки. Не используйте результаты без содержательной проверки экспертом. Подробности — в [QA.md](QA.md).

## Запуск в Windows

1. Скачайте `OntologyWorkbench-Windows-x64.zip` из [Releases](https://github.com/seregasmpl/ontology-workbench/releases).
2. Распакуйте весь архив в отдельную папку с правом записи. Папка `_internal` должна оставаться рядом с исполняемым файлом.
3. Запустите `OntologyWorkbench.exe`. Приложение откроет локальную страницу в браузере. Если вкладка не открылась, скопируйте адрес из окна приложения.
4. Создайте проект. Начать можно без ключа: описать онтологию и размечать примеры вручную.
5. Для обращения к модели откройте «Подключения» и укажите свой адрес API, модель и ключ.

Установка Python и Node.js для переносимой сборки не требуется. Сборка не подписана цифровым сертификатом; здесь не предлагается отключать защиту Windows. Это предварительная сборка для Windows x64, не проверенная на всех версиях системы.

Данные по умолчанию сохраняются в папке `data` рядом с программой. Закрытие вкладки браузера не останавливает приложение. Используйте «Завершить работу» или Ctrl+C в его окне. Для резервной копии сначала завершите работу, затем скопируйте всю папку `data`. Ключи из системного хранилища в эту копию не входят.

## Рабочий процесс

1. **Онтология.** Опишите задачу, единицу анализа и контекст. Добавьте понятия, определения, признаки включения и исключения, типы сущностей и направленных связей. Можно начать с шаблона или запросить предложение модели. Сохраняет правила эксперт.
2. **Примеры и разметка.** Генерируйте небольшие партии синтетических случаев или импортируйте тексты. Предполагаемый ответ модели скрыт до решения эксперта. Для категорий и связей указывайте доказательные фрагменты. «Не хватает контекста», «Не могу определить» и «Не подходит ни одна категория» — разные ответы.
3. **Данные.** Импортируйте TXT, CSV, JSONL или Parquet. Выберите поля текста, идентификатора, контекста и группы; явно подтвердите единицу анализа. Отмечайте синтетическое происхождение и закрытые материалы.
4. **Настройка и проверка.** Разделите реальные данные на настройку и итоговую проверку. Записи одной группы, нормализованные дубликаты и записи с одинаковым непустым контекстом не расходятся по наборам. Семантически похожие записи автоматически не обнаруживаются: эксперт должен связать их идентификатором группы.
5. **Версии.** Проверьте примеры запроса и зафиксируйте правила с параметрами модели. В запрос входят до 20 подтверждённых примеров настройки, но не проверочные ответы. Изменённые правила сохраняются новой версией; перенесённую разметку необходимо пересмотреть.
6. **Запуски.** Проверьте получателя, число записей и объём передаваемого текста. Запустите разметку, наблюдайте прогресс, останавливайте и продолжайте задание. Просматривайте ошибки и неопределённые ответы отдельно от найденных категорий.

«Обучение» здесь означает использование утверждённых правил и примеров в запросе. Программа не дообучает веса модели и не выдаёт универсальную оценку истинности онтологии.

## API и данные

Поддерживаются четыре протокола: OpenAI Responses, совместимый Chat Completions, Anthropic Messages и Gemini GenerateContent. Совместимость конкретной модели со структурированными ответами зависит от провайдера. Для генерации и разметки можно выбрать разные подключения.

Ключ хранится только до завершения сеанса либо в поддерживаемом системном хранилище секретов. В базу проекта и экспорт ключи не записываются. Адрес API и имя модели сохраняются как настройки подключения. Секреты не следует помещать в адрес, название модели или текст онтологии.

Локальное приложение не означает локальную модель: после подтверждения запроса провайдер получает текст, контекст, правила и примеры настройки. Запросы могут быть платными. Параметры хранения данных определяет выбранный сервис. Отметка «закрытый материал» ограничивает экспорт по умолчанию, но не шифрует базу и не запрещает подтверждённую передачу в API. Подробнее — [SECURITY.md](SECURITY.md).

Ошибка API, отказ, повреждённая структура ответа и неверная цитата не превращаются в отрицательную метку. Повтор обрывшегося запроса может повторно тарифицироваться провайдером, хотя уже сохранённые успешные результаты задания не дублируются.

## Экспорт

- Зафиксированная онтология — JSON с версией схемы, правилами, параметрами модели и разрешёнными синтетическими примерами. Реальные и проверочные тексты в такой пакет не входят.
- Результаты задания — ZIP с JSONL и CSV, отдельными таблицами сущностей и связей, агрегатами и манифестом.
- Закрытые записи исключаются по умолчанию. Их включение требует отдельного подтверждения. Даже при выключенном экспорте полного текста доказательные цитаты остаются частью результата; проверяйте файл перед публикацией.

## Запуск из исходников

Нужны Python 3.11 или новее и Node.js с npm; проверенная конфигурация — Python 3.12 и Node.js 22 на Windows x64. Команды выполняются из корня этого репозитория.

Windows PowerShell:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e '.[dev]'
Push-Location frontend
npm ci
npm run build
Pop-Location
.\.venv\Scripts\python.exe -m workbench.launcher
```

Linux и macOS:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -e '.[dev]'
(cd frontend && npm ci && npm run build)
.venv/bin/python -m workbench.launcher
```

На Linux системное хранение ключа требует доступного Secret Service; при его отсутствии выбирайте хранение на время сеанса. Запуск из исходников на Linux и macOS описан, но в этой поставке не проверен.

Дополнительные параметры запуска:

```text
--port 8765            выбрать постоянный локальный порт
--data-dir PATH        выбрать отдельную папку данных
--no-browser           не открывать вкладку автоматически
```

Для разработки интерфейса запустите сервер с `--port 8765`, а в папке `frontend` — `npm run dev`. Производственная сборка обслуживается самим FastAPI, отдельный сервер интерфейса не нужен.

## Проверки и сборка

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m ruff check backend tests
Push-Location frontend
npm run build
Pop-Location
.\.venv\Scripts\python.exe -m PyInstaller --noconfirm OntologyWorkbench.spec
.\.venv\Scripts\python.exe tools\collect_licenses.py
.\.venv\Scripts\python.exe tools\package_release.py
```

`requirements-lock.txt` фиксирует пакеты среды, в которой проверялась Windows-сборка. Для других систем используйте зависимости из `pyproject.toml`: некоторые пакеты lock-файла относятся к Windows. В ZIP исходников не входят базы, ключи, исследовательские архивы и зависимости окружения.

## Учебный текст

[Онтологии в анализе социальных данных с помощью ИИ](deliverables/Онтологии%20в%20анализе%20социальных%20данных%20с%20помощью%20ИИ.docx) — редактируемый DOCX, редакционный черновик раздела учебника. В нём последовательно разобран вымышленный пример сообщений жителей, уточнение правил и пределы выводов по автоматической разметке. Финальная постраничная проверка последней редакции ещё не завершена; фактический объём после неё нужно подтвердить.

Исходник документа — `tools/build_chapter.py`, зависимость для его сборки — `python-docx`. Опоры текста: [Noy и McGuinness](https://protege.stanford.edu/publications/ontology_development/ontology101-noy-mcguinness.html), [Grimmer и Stewart](https://bstewart.scholar.princeton.edu/publications/text-data-promise-and-pitfalls-automatic-content-analysis-methods-political), [Gruber](https://tomgruber.org/writing/ontolingua-kaj-1993.pdf). Учебные сообщения и файлы в `examples` синтетические и не подтверждают качество на реальных данных.

## Границы версии

Только текст, категории, сущности и типизированные связи. Нет совместного серверного редактирования, обработки изображений, полноценного OWL-редактора и обучения весов. Итоговые показатели отражают совпадение с конкретной экспертной разметкой, а не объективную правильность описания социальной реальности.
